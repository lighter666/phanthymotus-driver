# Bumi 固定资产借还 Skill 原型

员工可以向 Bumi 提出**借用或归还请求**。Bumi 使用人脸卡片核验当前员工，读取安装时导入的资产目录快照，生成给**同一位资产管理员**的飞书待转发消息。管理员统一保管固定资产台账：收到借用请求后核对并交付；收到归还请求后等候员工携物品到场，现场验收并人工登记。两种请求都不是交接完成记录。

当前环境提供的 `channel_reply` 只能回复本次触发的飞书会话，或向已配置的对端机器人协作；现场语音请求不能用它主动私聊指定人。因此本版**只生成待人工转发消息，不自动通知管理员**。管理员验收后可从飞书主动发确认消息；Skill 验证本次事件发送者 ID 与唯一管理员配置一致后，才用 `channel_reply` 回复核对摘要。无库存事务或台账写入工具，候选资产未预留，归还请求未完成验收，CSV 只是统一台账的人工维护快照。

## 配置

[assets.csv](assets.csv) 初始只有表头，不含虚构资产。每件资产一行，UTF-8 CSV：

| 字段 | 用途 |
| --- | --- |
| `asset_id` | 唯一资产编号，保留字母、前导零和连接符 |
| `asset_name`、`category` | 名称与员工借用时匹配的类别 |
| `sn` | 序列号；留空则显示“未提供” |
| `accessories` | 配件清单；没有配件请写“无” |
| `status` | 人工快照状态，仅“可用”“借出”“停用” |

[administrator.json](administrator.json) 只配置一位管理员：`name` 是姓名，`feishu_open_id` 是该人在当前飞书应用下可由事件验证的发送者 ID。初始两项留空；填入真实值前不能认定飞书确认人的管理员身份。管理员信息不逐资产重复填写。CSV 的可用状态不能代替管理员掌握的实时台账，多个申请可得到同一候选编号。

## 现场流程

**借用：** 问要借什么 → 人脸核验 → 从可用目录提出一件“未预留”候选 → 生成给管理员的待转发消息 → 员工转发并等待管理员核对、交付。管理员实际交付后人工更新统一台账和 CSV。

**归还：** 问要还什么及资产编号（没有则待现场核对） → 人脸核验当前归还人 → 生成给管理员的待转发消息 → 员工携主设备和配件去管理员处。管理员收到消息后等候到场，核对原借用记录、资产编号、SN、配件和可见差异；实物接收后可从飞书向 Bumi 发送确认。Skill 只能回复该飞书触发消息，不能仅凭员工的归还请求声称“已归还”。原借用记录缺失或存在差异时明确标注，管理员人工更新统一台账和 CSV。

## 安装与检查

在 Bumi 主机复制整个目录。填写真实资产和唯一管理员配置，再运行：

```bash
python3 scripts/install_local_skill.py --validate-assets
python3 scripts/install_local_skill.py
python3 scripts/install_local_skill.py --check
```

脚本默认操作 `/opt/phanthy-motus/data/data.db` 的 `config.skills`。数据库、CSV 或管理员配置位于其他位置时分别指定 `--db`、`--assets`、`--administrator`。安装先备份旧配置，按 slug 更新且保留其他 Skill，再重新读取验证。检查版本应为 `5.0.0`；CSV 或管理员配置变化后须重新安装并重新激活 Skill。推送 GitHub 不会自动安装到 Bumi。

本地运行 `python3 -m unittest discover -s tests -v`。Bumi 可连接后，实测借还两条现场分支、待转发状态、人脸实际返回值、管理员飞书事件的发送者 ID 和 `source_message_id`，以及管理员验收后的摘要。本地测试不能证明消息已转发、资产已交付或台账已更新。
