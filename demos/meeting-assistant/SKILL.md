# 会议全流程助手

当用户要求组织、主持、复盘或跟进会议时使用本 Skill。会议状态和任务以 `meeting_manager` 卡片返回的数据为准；不要仅凭对话记忆宣称任务已保存。

1. **会前**：用 `meeting_manager.create` 建立会议，填写标题、参会人和议程时长。请主持人逐项确认参会人、投影、网络等设备；调用 `meeting_manager.check_robot`，它会读取 Bumi 现有 `health_check`。只有 `preflight_ready=true` 才能说“全部就绪”。若 Bumi 返回异常、数据不足或连接失败，要直述原因。用户仍可决定开始会议，但不能误报就绪。
2. **会中**：使用 `begin_meeting` 开始当前议程。计时由会议服务负责；确认画布 `meeting_audio` 的输出接到了 Bumi `speaker` 输入，并检查页面播报状态。把明确达成的结论记录为 `record_decision`；把可能的后续工作记录为 `record_draft`。二者不能混淆。每项议程到时后由主持人决定调用 `next_agenda`；不要自动跳过讨论。结束时调用 `end_meeting`。
3. **会后**：读取会议与草稿。逐项向主持人确认负责人、带时区的截止时间、交付物、验收人、可观察的验收标准。缺任一项时保持草稿；只有主持人明确确认，才调用 `confirm_task` 且传入 `confirmed=true`。调用后再次读取任务列表，向主持人展示实际保存的内容。
4. **跟进**：通过 `list_tasks` 查看将到期、逾期、待验收任务。负责人提交完成说明或证据后调用 `submit_task`；验收人审阅后调用 `review_task`，不通过时填写退回原因。页面内显示状态，不向参会人自动发消息。不要替负责人提交或替验收人通过。

演示入口为会议服务任务板 `http://<Bumi-IP>:15740/`。首版由主持人在页面输入文字；不录音、不自动识别参会人。任务板的姓名输入是演示用途，不构成身份认证。
