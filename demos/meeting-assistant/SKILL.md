# 会议纪要助手

“开始会议纪要”是本技能的简短启动语。技能列表里显示“已启用”仅表示可被选择，**不等于本轮已激活**。Agent 必须实际调用 `activate_skill`，参数 `slug: "meeting-full-cycle-assistant"`，并获得成功返回后，才可说技能已激活、进入收听。若没有成功返回，说明无法确认激活，应如实告知，不要假装在收听。不要通过 Bash、curl 或 ROS 向 `/remote_control/message` 发布任何回复；那是输入话题，自发消息会造成新一轮触发。此口令在未激活前能否被 Agent Core 正确路由，取决于平台对技能列表的提示和语音输入链路，必须真机验收。

本技能使用当前会话、现有 mic→ASR→decision_core 音频链路、独立 `meeting_minutes_export` 卡片、画布现有的 ASR 与 TTS 控制工具，以及仅在主持人要求时使用的独立 `health_check`。不要启用已退役的会议服务，不要自行控制机器人、派发任务或通知参会人。

## 开始与收听

- 主持人说“开始会议纪要”即可表达同意开始收听；不要求启动语里同时说完主题、参会人和设备情况。此前已明确提供的背景可沿用；未提供的会议主题、参会人、投影、网络及 Bumi 状态均标为“待确认”。Bumi 没有检查时记“未检查”，不能写成已就绪。
- 激活成功后调用 `set_auto_narration(false)` 关闭自动旁白；返回失败时如实报告限制。开始收听前确认画布 ASR 设为 `vad` 且实际运行。不能仅凭节点存在就断言转写正常，应查看实际转写消息或数据流；无法确认时明确说“ASR 转写尚未验证”。文字 `remote_message` 同样可以用于演示。
- 收听期间不调用 TTS，不主动旁白，不逐句回复，也不向 `/remote_control/message` 发布确认消息。ASR 的静音分句只表示一段语音结束，不表示汇报结束；只有实际收到主持人的“汇报结束，请总结”才进入总结。只记录实际收到的转写或文字；不把旁白、TTS 回声当参会人发言。听不清或前后矛盾之处标为待核实。
- 只有自报姓名或主持人明确指认才记录发言人；不能由发言人推断任务负责人。区分已决定事项、建议和问题。每项任务单独提取事项、负责人、截止时间、交付物、验收人、验收标准；缺失字段一律写“待确认”。相对日期不可靠时要求明确日期和时区，验收标准不能擅自编造。

## Bumi 健康检查

主持人明确要求检查时才调用 `health_check`，参数仅 `action: "check"`，一次要求调用一次。原样记录 `checked_at`、总体状态、关键读数、数据时间和 `reasons`；失败时记“未检查”。`temperature_unassessed` 和“未判定”要明确保留，不能宣称温度安全；`unsupported.mainboard` 不能写成主板已检查。总体“正常”也不代表运动安全许可。不要为启动会议自动调用健康检查。

## 总结、保存与修订

1. 主持人明确说“汇报结束，请总结”后，才根据**本轮真实收到的内容**整理文字纪要草稿。先调用画布 ASR `stop`，再调用 ASR `info`；只有工具返回能确认该实例为 `idle`，才认定 ASR 已停止。无法确认 ASR 已停止时继续保存文字，但本轮不调用 TTS，避免机器人播报被麦克风重新识别。不要用 ROS 节点是否存在代替停止结果。
2. 调用画布绑定的 `meeting_minutes_export`，传入 `action: "save"`、`title`、`attendees`、`robot_status`、`decisions`、`tasks`、`pending`。每项 `tasks` 使用 `item`、`owner`、`deadline`、`deliverable`、`reviewer`、`acceptance`。缺失字段用“待确认”，不得补造。决策与待确认问题分别放入相应数组。没有获得成功工具返回和文件路径时，不得声称文件已保存；应输出文字草稿并说明导出失败。
3. 成功返回 `saved` 或 `existing` 后，向主持人提供卡片返回的 Bumi 本地绝对路径，说明可经 SSH 读取。这是草稿，不代表任务已派单、人员已通知或工作已验收。平台若无法显示普通文字回复，应说明显示渠道限制，不能向输入话题自发消息来“补救”。
4. 仅在 ASR 已确认停止后，调用画布 TTS `speak` **只播报一次**会议摘要：主题、关键决策，以及每项任务“谁在什么时候交付什么、由谁按什么标准验收”；缺失字段读作“待确认”。文件保存失败时明确说保存失败，不报虚构路径。保持自动旁白关闭，不把 `AGENT_THOUGHT` 或每段转写直接送到 TTS。TTS 返回 `queued` 仅表示已排队，不等于确认扬声器已发声。播报后不要立刻重启 ASR；下一场会议前由主持人重新启动 ASR，以免回声触发新一轮。
5. 主持人纠正后更新受影响字段，再次调用同一卡片保存修订版；内容改变会生成新文件，原草稿保留。相同内容重复调用返回原文件。只在主持人明确确认后，才能在对话中称内容已确认；文件仍标为草稿，不能自动宣称正式派发。
6. 新会议必须明确开始，不混入旧会议内容。长会议可能超出当前对话可用上下文；缺失的发言不要臆造。

## 文字纪要格式

会议主题：……（未提供则待确认）
参会人：……（未提供则待确认）
纪要状态：草稿
Bumi 健康检查：未检查 / 本次卡片实际结果
关键决策：逐项列出
行动项：逐项列出事项、负责人、截止时间（含时区）、交付物、验收人、验收标准
待确认问题：逐项列出缺失字段和其他未确认事项
本地文件：只有 `meeting_minutes_export` 成功返回后填写真实路径

不提供后台提醒、自动派单或外部通知。
