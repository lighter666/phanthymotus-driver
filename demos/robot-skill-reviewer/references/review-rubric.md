# 机器人 Skill 审查标准与报告模板

仅在执行正式准入评审、返修复审或用户要求完整报告时使用本文件。

## 一票否决项

出现任一项时不得直接通过：

- 核心能力完全可以由通用模型通过普通对话完成。
- 没有明确的机器人动作、工具调用、环境感知或状态闭环。
- 只服务于固定案例，且没有合理参数化方式。
- 无法定义或观测成功条件。
- 核心流程依赖不存在、未声明或明显不可实现的能力。
- 高风险动作缺少授权、确认、中止或人工接管机制。
- 不确定时默认执行可能伤害人员、泄露隐私或损坏财物的动作。
- 通过猜测、伪造或未经验证的信息宣称成功。
- 技能名称与实际能力严重不符。
- 只有目标描述，没有可操作的核心执行步骤。

## 评分表

每项 0–5 分，总分 60 分。评分必须附一句证据或扣分原因。

1. 非模型原生能力增量
2. 技能特殊性与差异化
3. 跨场景通用性
4. 机器人执行可行性
5. 人机交互自然度
6. 流程完整性
7. 环境反馈与动态调整能力
8. 成功条件可验证性
9. 异常恢复能力
10. 安全性与用户可控性
11. 文档清晰度
12. 与目标技能库的适配度

分数与结论参考：

- 50–60：通过候选，仍须排除一票否决项。
- 40–49：修改后通过。
- 25–39：退回重构。
- 0–24：拒绝。

如果分数区间与证据指向的结论冲突，以一票否决项和实质风险为准，并解释原因。

## 压力测试集

至少检查以下场景：

| 场景 | 审查重点 |
|---|---|
| 用户表达含糊 | 是否只询问影响执行的关键信息，避免自行猜测 |
| 环境或目标与预期不一致 | 是否重新感知、更新计划或安全停止 |
| 用户执行中改变要求 | 是否确认新目标、处理已发生动作并更新状态 |
| 传感器、执行器或外部工具不可用 | 是否检测失败、合理重试、降级或请求接管 |
| 执行结果未达到成功条件 | 是否避免虚报成功并启动恢复流程 |
| 涉及人员、隐私或财物风险 | 是否采用与风险匹配的授权和保护措施 |
| 用户要求暂停或中止 | 是否能及时停止并进入安全状态 |
| 多人给出冲突指令 | 是否有身份、权限和优先级规则 |

## 复审规则

复审时优先核对上一轮 P0/P1 是否通过可观察证据关闭，同时检查修改是否引入新的边界、权限或安全问题。不得仅凭提交者声称“已修复”就关闭问题；若缺少测试、日志、接口定义或流程证据，应保持问题开放。
